## 申请时，说明你准备做什么

不需要写一份很长的申请书。先把下一阶段讲清楚：

- 研究什么问题，已经有哪些基础？
- API 准备用在哪里，大约需要多少调用，估算依据是什么？
- 希望在什么时间完成哪一步？
- 会留下哪些别人可以使用的代码、案例、方法或研究记录？

如果已有项目或讨论，附上链接就好。有些材料不方便公开时，说明类型和原因即可。

## 怎样决定支持

公共额度有限，采用申请审核的方式。审核关注目标、计划、资源需求与开放交付，学历和机构不是硬性条件。批准时会明确额度、有效期和联系人。

通常先支持一个范围清楚的小阶段。准备继续时，带着实际使用情况、阶段结果和下一步计划申请续额。

## 把每一阶段的经验留下来

一次尝试可能排除了一条路线，也可能带来新的问题。把方法、观察和下一步的想法记录下来，既能帮助你决定是否继续，也能给遇到相似问题的人一些参考。

接受支持前，申请者和维护者会约定要开放的成果及许可。已有的私人资产和个人工作轨迹不属于默认交付。API 密钥通过私密渠道提供，不放进公开帖子或仓库。
