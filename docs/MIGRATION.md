# 迁移到正式账号

代码、文档和素材可以重新部署；GitHub 平台状态需要单独处理。

## 迁移前

记录当前组织与仓库、默认分支、维护者、开放申请、讨论类别、标签、分支规则、Secret 名称（不记录其值）。保存所有已发布版本及原始署名、许可和素材来源。

可选择直接转移仓库，或在新组织创建仓库后复制内容。仓库转移的实际限制、重定向和组织设置须在操作时核验；重新创建不会自动保留 Issues、PR、讨论或审核历史。只复制 Git 提交不能替代这些记录。

## 本地改路由

```powershell
python tools/rebrand.py --profile ../Shenyan-kosmoX-profile --organization YourActualOrg --maintainer YourActualMaintainer
```

默认只报告。确认目标与权限后，在副本或工作分支中加 `--apply`。迁移前先明确停用已开放的资源申请。脚本只修改本地配置和明确的社区链接，不调用 GitHub；保持资源入口关闭，并将讨论入口标记为未启用，直到新组织实际设置完成。

迁移不会自动改写科研项目链接，因为项目可能仍在原位置。逐个检查 `community.json` 中的真实项目 URL。许可证中的历史权利人和科研贡献记录也不自动改名。

## 平台上重新核对

- 组织简介、头像与公开 `.github/profile/README.md`。
- 维护者访问权、CODEOWNERS、分支规则及必要检查名称。
- Discussions 和表单 slug、标签、Issue 模板入口。
- Actions 开关、首次外部贡献审批、资源用量。
- Secrets：在目标重新配置，绝不导出明文到仓库。
- API 实际预算与私密交付安排；确认后再开启申请。
- 旧链接与新链接的跳转或说明。

## 验收

在本地运行结构检查与测试；在新组织实际打开主页和参与入口，提交一项明确标为迁移核查的 PR，检查失败与修复路径。验证器正常运行不等于已有科研项目已经得到新一轮科学审核。

GitHub Free 支持的公开仓库保护机制不能直接假设同样适用于私有仓库。若迁移同时改变可见性，需要重新评估功能与公开范围。
