# 科研交付约定 v1

目的：让后来者知道怎样运行、怎样判断，以及哪些结论尚不能成立。结构应服务研究问题，不要求每项贡献成为可自动评分任务。

## 文件与版本

代码、文档、必要小型数据进入 Git。大文件通过版本化 Release 或有明确许可的存储提供；记录稳定地址、大小与 SHA-256。不能只依赖个人绝对路径或未说明的本地缓存。

`research.json` 描述一个版本的运行入口和证据位置。环境声明至少包含：Python 版本、支持平台、依赖文件、实际项目联系人、许可说明、最小案例、验证方式及限制。

## 任务类别

| 类别 | 验收关注 |
| --- | --- |
| reproduction | 对应论文或独立基线、固定条件、可比观测量、已知差异 |
| development | 新增能力、接口、适用范围、回归与独立控制 |
| exploration | 问题、方法、过程与证据质量；允许阴性或未定结果 |

## 判断依据

**验收依据**定义完成标准；**独立参照**说明支持比较的来源；**验证方法**执行或描述检查。三者分别记录。测试数量、曲线相似或 PR 合并都不自动代表科学正确。

物理结果的证据要求应对应主张、观测量和相关尺度。数值收敛、实现错误、模型表示限制和来源不确定性分开记录。不为了通过审核追溯放宽容差。

## 命令

命令以参数数组记录，审核器不使用 shell 拼接。`install` 在独立环境安装项目依赖；`smoke` 运行最小案例；`verify` 运行与证据有关的检查。没有自动科学验证的探索项目可以将 `verify` 留空，但必须说明人工审核方法，此时报告为“未执行自动科学验证”，不能显示验证通过。

记录每个命令的超时预算。工程 CI 仅在声明支持的平台执行；重型计算可人工运行并附机器、版本、时长和结果，不伪称 CI 已验证。

## 结果与授权

保留模型假设、配置、输出、差异和失败。参考材料应有来源与许可；私人轨迹不属于默认交付。贡献认可见 [引用与认可](RECOGNITION.md)。
