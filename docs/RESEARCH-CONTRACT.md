# 怎样整理一份方便接续的项目

第一次使用的人想知道项目能帮上什么忙、怎样开始；准备贡献的人还需要找到相关方法、代码和检查。SORS 把这些入口连接起来，让项目的使用、讨论与维护更顺畅。

当前正式约定是 [SORS 0.1](../standards/SORS/README.md)。本页介绍整理思路，完整字段见[技术附录](../standards/SORS/TECHNICAL-FORMAT.md)。

## 先让读者看到完整工作

首页说明研究问题、主要能力和已经取得的成果，再给出快速开始。完整案例目录可以覆盖多篇文献比较、独立基准和探索性研究；第一次运行选择一个短小例子。二者共同帮助读者了解项目的积累与使用方式。

每项能力和案例都应有实际入口。已经实现的模块、已有结果、当前假设和待研究的问题分别说明，读者就能选择与自己目标相符的部分。

## 用索引连接已有材料

项目根目录使用一个 `research.yaml`、`research.yml` 或 `research.json`，统一声明 `schema_version: '0.1'`。每个研究案例使用一个案例清单，通常命名为 `case.yaml`。文件扩展名可以不同，字段含义遵循同一份规范。

| 读者想找的内容 | 项目中怎样安排 |
| --- | --- |
| 项目用途、维护者和贡献方式 | README 与贡献入口 |
| 模型、方法与适用范围 | 研究说明或已有专业文档 |
| 可以调用的能力 | 能力目录及对应接口说明 |
| 使用条件与运行方式 | 环境、依赖文件、安装说明与案例步骤 |
| 具体研究问题和结果 | 案例索引、配置、报告与计算产物 |
| 判断结果的依据 | 文献或独立参照、检查方法、指标和原有容差 |
| 来源、复用与引用方式 | LICENSE、第三方说明与引用信息 |

同一份文档可以承载多项说明。已有 `src/`、`studies/`、`research_cases/` 或历史结果目录都可以保留，索引指向真实位置即可。

## 每个案例连接什么

一个案例围绕具体问题，说明输入、模型、关键参数、方法、执行步骤、预期产物、判断依据和实际结果。使用多个环境的项目，案例引用自己需要的环境；同一环境可以供多个案例共用。

执行步骤分为可直接运行的命令和文档化操作。命令使用参数数组，明确工作目录、依赖步骤和超时；需要专门设备、外部求解器或较长计算时间的操作，按实际条件写清准备方式。结果文件可以附数组含义、单位、生成版本或源文件摘要，方便后续比较。

案例阶段和结果状态分别记录。计划中的工作写明已有材料与下一步检查；已有结果可以包含差异、失败和未定结论。历史结果已经完成、当前环境尚未恢复，也能同时说明。

## 保留学科自己的表达

计算光子学关心几何、介电张量、频率单位和开放边界；生态动力学关心状态方程、扰动度量、时滞历史和事件规则。这些内容可写在领域扩展与现有配置里，共同索引负责把它们与案例连接。

判断依据随研究问题确定。检查覆盖什么观测量、参照来自哪里、误差与相关物理尺度怎样比较，都应能从案例找到。对差异先区分数值、实现、模型和来源假设，修订判据时保留旧版本与理由。

## 安排文件与较大结果

代码、文档和必要的小型数据进入 Git。较大结果可通过版本化 Release 或其他稳定存储提供，记录地址、大小、SHA-256 和读取方法。暂未分发的历史材料使用 `availability: not_bundled`，说明保留了哪些记录，以及材料的取得或重建方式。

许可证分别覆盖自有代码、第三方素材和数据来源。使用者应能从来源页找到原始论文与上游工具，也能知道怎样引用当前项目。

## 从现有例子开始

[EcoDynamics](https://github.com/Shenyan-kosmoX/ecodynamics) 与 [Floquet–Maxwell](https://github.com/Shenyan-kosmoX/floquet-maxwell) 已采用 SORS 0.1，可以直接查看项目与案例索引。社区的[通用研究方法论](../standards/SORS/COLLABORATION.md) 可按需要参考；项目提交包含公开研究材料，聊天记录与详细协作回顾由作者自行决定是否分享。

早期 [Python 参考包](../templates/research-project/README.md) 保留 `schema_version: 1` 的运行协议，供既有项目维护与迁移参考。新接入项目使用 SORS 0.1。
