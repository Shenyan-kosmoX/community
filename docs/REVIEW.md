# 提交以后怎样审核

## 首次接入项目

先在 [项目提案区](PROJECT-INTAKE.md) 介绍用途与进展，再整理准备公开的版本。我们会根据首批真实项目，确定项目组成和首轮自动检查要求。

目前公共仓库已经运行文档、链接和表单检查；[科研项目参考包](../templates/research-project/README.md) 提供 Python 项目安装、小案例与验证的工作流，供接入时调整。

## 提交改动

创建 PR 后，自动检查结果会显示在页面下方。检查失败时，打开对应记录查看错误，修正后继续提交到同一分支即可。

较小贡献和日常修改由内部成员审核。审核者结合改动和运行记录提出意见，作者在 PR 中回应并补充。模型、参考数据或判断标准有变化时，说明修改的理由，方便大家检查其影响。

## 结果有分歧

把各自的观察、依据和仍有疑问的部分留在 PR。需要更多人一起讨论时，在 Discussions 发帖并回链 PR。分歧可以保留，维护成员会说明这次接受了哪些修改、哪些问题继续讨论。

自动检查回答文件与程序是否按约定工作，科学判断还需要结合方法与证据审阅。审核记录写清检查人、范围和结论。

## 查看具体规则

运行环境、检查名称和权限设置见 [维护说明](OPERATIONS.md)。需要借助 AI 阅读改动时，可以参考 [AI 审阅提示](AI-REVIEW.md)。
