# 写下你为什么做这个项目

使用说明让别人知道怎样运行，开发记录则让人认识背后的选择。它可以是一篇文章，也可以是随着工作陆续补充的几段笔记。

## 从你记得最清楚的一段开始

最初遇到了什么具体问题？你当时手里有什么，觉得还缺什么？可以从一次计算、一篇文章或一件反复需要处理的工作讲起。

接着写一次真正影响方向的尝试。原来怎样想，实际发生了什么，后来为什么换了方法。相关的图、代码版本或讨论可以链接过来，供感兴趣的人接着看。

## 把自己的判断讲出来

如果与 AI 一起开发，可以讲它在哪一步帮到了你，哪一步需要自己重新检查，以及你怎样作出取舍。读者最想知道的，往往是一个看似顺利的结果之后，你为什么还决定多问一句。

## 留一个可以接下去的地方

现在最想解决什么？别人可以从哪部分试用、验证或改进？链接到具体 Issue，便于有兴趣的人找到下一步。

文章写在项目仓库里即可，例如 `docs/development-notes.md`。README 放一个“为什么开发这个项目”的入口，再从文章链接回运行案例。个人经历用自己的名字署名，团队共同作出的选择说明参与者。

开发记录可以晚于代码发布。先留下你愿意讲的一段，后面有新进展时再继续写。
