# 把你的项目带进来

你可能已经写了一套计算工具，也可能刚跑通一个实验。如果希望继续维护它、邀请别人一起研究，可以先介绍一下。研究中用到的阅读、整理、写作等 skill，也欢迎说明它解决的具体问题。

[介绍我的项目 →](https://github.com/Shenyan-kosmoX/community/discussions/new?category=ideas)

## 第一篇帖子写什么？

可以沿着下面几件事介绍，也可以用自己的方式讲：

1. **为什么开始做？** 是什么问题让你愿意投入？
2. **已经做到哪里？** 附仓库、案例或研究记录，让别人看到可以使用的部分。
3. **最想推进哪一步？** 是复现结果、改进方法，还是检验一个新想法？
4. **希望别人怎样加入？** 例如一起核对推导、测试工具、补充文档。
5. **接下来谁来维护？** 介绍你准备负责的部分，以及愿意开放的材料。

## 发出以后怎样推进？

首版由 [@wenkuizhao261-pixel](https://github.com/wenkuizhao261-pixel) 接手项目提案，负责与你沟通，并决定项目接入。发帖时可以提及这个账号，后续材料也补在同一帖子里。

接下来会一起确认：先整理哪个运行案例、怎样检查结果、代码和材料采用什么许可，以及别人可以从哪项工作开始参与。确认接入后，把实际仓库、作者和使用入口加入 [研究目录](RESEARCH.md)。项目仍由作者继续维护。

## 给第一次使用的人准备些什么？

选一个能跟着做的案例，写清安装方式、输入和运行步骤，并附上输出示例。科研计算项目再说明模型、参数、参照依据和结果适用的范围；写作或其他工具则展示实际输入、输出，以及使用时需要自己调整的地方。

[项目交付说明](RESEARCH-CONTRACT.md) 列出了具体内容。已有项目可以沿用自己的组织方式，[参考模板](../templates/research-project/README.md) 供需要时取用。

## 也可以写写你为什么做这件事

工具有使用说明，开发者也有自己的选择。最初遇到了什么、试过哪些方法、为什么最后这样设计，都可以留在 [开发记录](DEVELOPMENT-NOTES.md) 里。先写其中一段，后面再慢慢补充。

需要 API 额度时，可以了解正在筹备的 [研究支持计划](RESOURCES.md)。
