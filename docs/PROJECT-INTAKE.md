# 把你的项目带进来

你可能已经写了一套工具，也可能刚跑通一个小实验。如果你希望继续维护它、邀请别人一起研究，可以先介绍一下。

## 第一篇提案，回答几件事就够了

在 [项目讨论](DISCUSSIONS.md) 中说明：

1. **你在研究什么？** 什么问题让你愿意持续投入？
2. **已经做到哪里？** 附代码、案例或研究记录，指出目前能运行的部分。
3. **最想推进哪一步？** 是复现一项结果、补一个方法，还是检验一个新想法？
4. **希望别人怎样参与？** 例如一起核对推导、改进算法、写使用说明。
5. **你愿意维护哪些部分？** 也说说希望共享哪些材料、有哪些公开限制。

这些内容不必一次写得很完整。维护者会据此讨论接入范围；有缺项时，在原提案中补充即可。

## 让第一次使用的人能够跟着做

正式加入目录前，选一个小案例，写清依赖、输入和运行步骤。把预期观察、参照依据与尚未解决的问题放在一起，方便别人运行以后知道该看什么。

如果结果与论文不同，就把差异留下。如果研究还没有答案，就说明准备通过什么实验或计算继续判断。

[科研交付约定](RESEARCH-CONTRACT.md) 列出了具体内容；[项目模板](../templates/research-project/README.md) 可以按需取用。已有项目可以保留自己的目录，通过 `research.json` 指向相应文件。

## 接下来会发生什么

维护者在提案中说明是否接入、还需要补什么，或者为什么暂缓。确定负责人、公开范围和运行入口后，通过 PR 将项目加入目录。

需要 API 额度时，可以另行查看 [研究支持](RESOURCES.md)。项目接入与资源申请分别处理。
