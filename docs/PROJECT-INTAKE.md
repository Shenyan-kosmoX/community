# 一个项目怎样加入

项目可以从一个可靠的小案例开始。申请接入不要求完整平台，也不要求拥有论文或机构身份。

## 先讨论

按 [讨论指引](DISCUSSIONS.md) 提交项目提案：研究问题、已有材料、当前可运行范围、希望共同推进的方向、维护意愿和公开许可。没有验证过的部分直接标明。

## 接入前核对

1. 有真实的代码或研究材料，并说明当前状态。
2. 有明确维护联系人。
3. 选定一个最小运行路径，记录支持平台和依赖。
4. 明确验收依据与验证边界；探索性工作可以没有参考答案。
5. 公开范围和第三方许可得到确认。
6. 有少量真实的后续任务，并能接收贡献。

完整要求见 [科研交付约定](RESEARCH-CONTRACT.md)。已有项目可保留原结构，通过一个 `research.json` 连接所需文件，不要求大规模搬家。

## 审核和登记

维护者在提案中记录接纳、补充材料或暂缓的理由。接纳项目不认证其全部科学结论，也不自动获得 API 额度。确认后，通过 PR 更新目录配置，链接实际仓库和负责人。

## 参考包

使用 [研究项目参考包](../templates/research-project/README.md) 起步或取用其中的文件。参考包尚无科研实现，按原样执行审核会因尚未定义实际交付而失败，这是有意保留的接入门槛。
