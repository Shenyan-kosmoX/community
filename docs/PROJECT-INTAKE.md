# 提交项目

社区接收以 AI for Science 为主线的科研项目，也欢迎研究与创作中使用的 skill 和工具。正式加入的项目放在 Shenyan-kosmoX 的组织仓库中，由作者继续维护。

[介绍你的项目 →](https://github.com/Shenyan-kosmoX/community/discussions/new?category=ideas)

## 先介绍用途和进展

第一篇帖子写清两件事：项目想解决什么问题，目前做到哪里。已有代码、样例或研究记录可以附上；也可以说说为什么开始、需要哪些帮助，以及准备怎样继续维护。

这一步用于了解项目。运行环境、验证和许可材料可以在接入过程中逐步整理。

## 确认项目怎样加入

目前由 [@wenkuizhao261-pixel](https://github.com/wenkuizhao261-pixel) 接手提案和接入决定。沟通留在原帖子里，包括准备开放哪些内容、组织内采用哪个仓库，以及由谁维护。

作者已有仓库时，先确认转入组织或将准备公开的内容整理到组织新仓库的方式，再实际操作。接入后，项目 README 列出作者、维护联系人和贡献入口。

## 整理可以共同维护的版本

正式项目采用 [SORS 0.1](../standards/SORS/README.md)。它约定研究说明、实际资产、运行环境、案例和结果各自在哪里，以及怎样相互连接。项目可以保留已有目录与专业写法。准备时，先把以下入口接起来：

- **认识项目**：用途、完整能力、已有成果、作者和维护者。
- **开始使用**：支持的环境、输入取得方式、运行或操作步骤，以及一个计算量适合入门的例子。
- **理解结果**：模型与假设、参考依据、检查方法、实际结果和适用范围。
- **继续参与**：来源与许可、反馈入口、已有问题和后续工作。

`research.yaml` 汇总项目入口，每个案例用 `case.yaml` 连接所需材料。小项目可以合并文档；大型项目把已有案例全部列入目录，再选择轻量入口帮助读者开始。已有结果、失败对照和仍在研究的内容都能按实际状态呈现。

[项目整理指南](RESEARCH-CONTRACT.md) 介绍阅读顺序；[提交规范](../standards/SORS/SUBMISSION-CONTRACT.md) 和[技术附录](../standards/SORS/TECHNICAL-FORMAT.md) 给出具体约定。通用研究方法论由社区维护，开发故事由作者自愿分享。

## 项目和 skill 怎样分类

每个项目按领域、提供形式和主要用途登记。领域可以有多个；一个项目既可以提供 Python 库，也可以提供 CLI 或 Agent skill。完整目录只保留一份项目条目。

多个 skill 共用同一套程序与版本时，放在所属项目中维护，目录链接到各自入口。你可以提交完整的工具项目，也可以提交能独立使用和维护的 skill；说明安装方式、依赖和使用案例即可。[目录整理方式](CATALOG.md)供维护者登记时参考。

## 发布与后续贡献

准备完成后，先运行结构检查，再结合项目条件核对一个使用入口和相应结果。维护成员审阅材料与发布范围，项目随后加入[研究目录](RESEARCH.md)。

后续小改动使用普通 PR 描述即可，说明改了什么、怎样检查，由内部成员审核。涉及模型、参考结果或判断标准的变化，再补充相应依据。方法或结果有分歧时，在 PR 保留不同意见，也可以邀请社区到 Discussions 一起讨论。
